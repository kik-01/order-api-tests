# JMeter 基础压测报告

## 结论

本次在本地单机环境执行 10 个并发用户、3 秒逐步启动、持续约 20 秒的基础压测。
下单写接口和商品查询接口共完成 2267 次请求，未出现 HTTP 错误或断言失败。

| 指标 | 结果 |
|---|---:|
| 并发用户 | 10 |
| 持续时间 | 20 s |
| 总请求数 | 2267 |
| 成功请求 | 2267 |
| 错误率 | 0.00% |
| 平均响应时间 | 25.62 ms |
| P95 响应时间 | 61.00 ms |
| 最大响应时间 | 257.00 ms |
| 吞吐量 | 114.25 requests/s |
| 响应码 | 201 × 1136，200 × 1131 |

## 场景

每次循环依次执行：

1. `POST /api/orders`：创建一张包含唯一幂等键的订单；
2. `GET /api/products/{id}`：查询压测商品。

请求间隔 50 ms。下单响应码断言为 `201`，商品查询响应码断言为 `200`。

## 环境

- Windows 本机；
- Python 3.14.7；
- Flask + SQLite；
- Apache JMeter 5.6.3；
- JMeter、Flask 服务和 SQLite 同机运行。

## 解读与限制

- 本轮目标是确认接口在基础并发下没有明显错误，并练习 JMeter 场景配置和指标解读；
- 0% 错误只能说明当前本地环境、当前数据量下未复现错误，不代表生产容量；
- SQLite 写锁、单机 CPU/磁盘竞争和本机网络都会影响结果；
- 本轮只覆盖单商品下单和商品查询，不包含支付、退款、多商品和真实网关；
- 更深入的性能测试需要独立压测机、MySQL、连接池、监控指标和更明确的 SLA。

## 复现

```powershell
python perf/run_load_test.py --threads 10 --ramp-up 3 --duration 20
```

JMeter 场景文件为 `order_api_load_test.jmx`。每次运行会在 `perf/results/` 下生成原始样本和 HTML 报告。
